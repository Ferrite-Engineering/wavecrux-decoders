# PCIe Data Link Layer receive stimulus

Ready-made `$readmemh` files for driving a PCIe Gen1/Gen2 receiver in an RTL
testbench: packets at every starting byte lane, back to back with no idle,
and the usual error cases mixed in with good traffic. Each `.hex` file has a
`.txt` manifest that lists every packet, where it is, and what a correct
Data Link Layer must do with it.

The files are built by the same encoder as the decoder fixtures
([`../tools/export_stimulus.py`](../tools/export_stimulus.py)): DLLP CRC-16
and TLP LCRC are computed from the packet contents. Before a file is written
it is read back and decoded by the reference decoder, and the export fails
unless the decoder finds exactly the packets in the manifest. CI runs the
same check, so the committed files always match.

## Files

| Case | What it holds |
|---|---|
| `every_lane_w64` | For each starting byte lane 0 to 7: an Ack, an MWr32, an UpdateFC-P and an MRd64, back to back. Packets cross word boundaries at every offset. |
| `back_to_back_w64` | Every defined DLLP type and every defined TLP type (TD/ECRC, EP, TC variety, a Msg whose Length field is 0, meaning 1024 DW), with no idle between packets. |
| `errors_w64` | For each starting lane: a DLLP with a bad CRC, a good TLP, a TLP with a bad LCRC followed by its retransmission, and a nullified TLP (inverted LCRC, ended by EDB) followed by its retransmission. |

Sequence numbers start at 0 in each file and only advance on a TLP that is
accepted, so a receiver that tracks `NEXT_RCV_SEQ` sees no sequence errors.

## Format

One line per PCLK, hex, most significant digit first:

```
{datak[7:0], data[63:0]}      18 hex digits per line
```

Byte lane `j` is `data[8j+7:8j]` with its K flag in `datak[j]`, and lane 0
is first in time (a x1 link with an 8-symbol PIPE word, or byte lane j of a
wider link). Scrambling is off and logical idle is D `0x00`. The first three
lines are `//` comments, which `$readmemh` skips.

The manifest gives each packet's first and last symbol as `word.lane`, where
`word` counts `.hex` data lines from 0:

```
  start     end  kind  seq  expect  why        label
    0.0     0.7  DLLP    -  drop    bad CRC    UpdateFC-P VC0 H=1 D=0 CRC mismatch
    1.0     3.7  TLP     0  accept  good LCRC  TLP seq=0 MWr32 len=1
    4.0     6.3  TLP     1  nak     bad LCRC   TLP seq=1 MRd32 len=1 LCRC mismatch
```

`expect` is `accept` (passed up), `nak` (rejected; the receiver schedules a
Nak) or `drop` (discarded silently: a DLLP with a bad CRC, or a nullified
TLP). The `label` column is what the `wcx-pcie` DLL decoder shows for the
packet in WaveCrux, so a waveform of the testbench run can be checked
against the manifest by eye.

## Using it

```systemverilog
localparam int N = 137;                    // data lines in the file (see the manifest header)
logic [71:0] stim [0:N-1];
int i = 0;
initial $readmemh("errors_w64.hex", stim);

always_ff @(posedge pclk) begin
  if (i < N) begin
    {phy_rx_datak, phy_rx_data} <= stim[i];
    i <= i + 1;
  end else begin
    {phy_rx_datak, phy_rx_data} <= '0;     // logical idle
  end
end
```

Count accepted TLPs and DLLPs, and the Naks the receiver schedules, and
compare them with the `expect` column. A receiver that frames packets
without looking at `datak` can be confused by payload bytes equal to STP
(`FB`), SDP (`5C`) or END (`FD`); the K flags are in every line for that
reason.

## Other bus widths

```
python3 decoders/pcie/tools/export_stimulus.py --lanes 4 --out <dir>   # 32-bit PIPE
python3 decoders/pcie/tools/export_stimulus.py --lanes 2 --out <dir>   # 16-bit
python3 decoders/pcie/tools/export_stimulus.py --lanes 1 --out <dir>   # 8-bit
```

Only the 64-bit files are committed. With N lanes a line is
`{datak[N-1:0], data[8N-1:0]}`.
